# Code of Conduct

## Purpose

Portfoliable is maintained as a collaborative technical project. This Code of Conduct defines the behavioral baseline required for healthy, productive collaboration.

## Scope

This policy applies to all project spaces, including:

- source code contributions
- pull request discussions and code review
- issue discussions
- release and incident coordination
- security disclosure collaboration

## Expected Behavior

Contributors and maintainers are expected to:

- communicate respectfully and professionally
- provide actionable, technically grounded feedback
- focus on behavior, code, and outcomes rather than personal attributes
- assume good intent while still holding quality standards
- document disagreements with clear rationale and reproducible evidence

## Unacceptable Behavior

The following are not permitted:

- harassment, threats, or personal attacks
- insulting, demeaning, or discriminatory language
- repeated hostile or disruptive behavior
- intentionally derailing technical discussion
- publishing private or sensitive information without permission

## Collaboration Standards for Technical Review

To keep review cycles efficient and safe:

- reviewers should identify concrete risks and regressions
- authors should respond with evidence, fixes, or clear trade-off reasoning
- unresolved concerns should be escalated constructively
- release-critical disagreements should prioritize reproducibility and rollback safety

## Enforcement Responsibilities

Maintainers are responsible for enforcing this policy consistently. Responses may include:

- private or public warning
- request to revise behavior
- temporary communication restrictions
- removal from project participation for severe or repeated violations

Enforcement decisions should be proportional to impact and risk.

## Reporting

If you experience or observe a violation:

1. report the incident to maintainers using project channels
2. include links, timestamps, and context whenever possible
3. avoid public escalation that reveals sensitive details unnecessarily

Security-related concerns should follow the disclosure process in `SECURITY.md`.

## Appeals

Contributors may request a secondary review of an enforcement decision. When possible, appeal review should involve maintainers not directly involved in the original incident.

## Commitments

By participating in this repository, you agree to uphold this Code of Conduct and support a respectful, high-signal engineering environment.
