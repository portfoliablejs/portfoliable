# Testamentus: a Bible reader built for focus

Testamentus is a multilingual Bible platform designed around a simple product belief: performance and reverence are part of the reading experience. Existing platforms often interrupted reading with ads, heavy interfaces, and five-to-twelve-second mobile loads. This project removed those distractions without turning the system into a static brochure.

[INSERIR IMAGEM 1 — fluxo Lean UX e telas do leitor, mostrando a relação entre descoberta, performance e foco.]

## Static-first, not static-only

The project uses MySQL as a source of truth and PHP as a compilation layer. More than 31,000 verses can be rendered into loose, semantic HTML pages, eliminating runtime database work for the core reading path. Search remains dynamic, while accessibility preferences and reading state persist in the browser.

```bash
[ MySQL Cloud Db ] ──(Local Compilation Engine)──> [ In-Memory Buffer (ob_start) ]
│
▼
[ GitHub (main) ] <──(Decoupled Logic Dev)        [ /public Static Asset Matrix ]
│
▼ (Automated Deployment Vector)
[ Hostinger Server (deploy) ]
```

The deployment keeps clean language and book paths, canonical URLs, and `hreflang` links available for global indexing. The architecture is deliberately modest: a shared server, a small monthly budget, and a compiler that does the expensive work before a reader arrives.

## Reading as a quiet interface

Research with pastors, educators, scholars, and casual readers showed three dominant tasks: read sequentially, find a verse, and change translation. That shaped the product surface. Times New Roman serves long-form reading; Arial handles controls; dark mode, font adjustments, reading direction, and keyboard-friendly navigation remain available without competing with the text.

[INSERIR IMAGEM 2 — leitor em modo claro e escuro, com controles de acessibilidade e troca de tradução.]

Sharing supports both contexts: a canonical verse URL for study and a generated image for social conversations. The interface stays free of ads, donations, and paywalls.

## A small routing layer

The static output is served directly, while Apache maps the search route back to the dynamic endpoint:

```apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^search$ search.php [L,QSA]
```

## Outcome

Testamentus reached a 0.9s First Contentful Paint and a 100/100 PageSpeed result in the original validation, with WCAG AA work targeting a 92/100 accessibility score. The result is a platform that can grow across languages while keeping the reader’s attention on the text.

# Testamentus: uma Bíblia digital feita para foco

O Testamentus é uma plataforma bíblica multilíngue construída a partir de uma crença simples: performance e reverência fazem parte da experiência de leitura. Muitas plataformas interrompem a leitura com anúncios, interfaces pesadas e carregamentos mobile de cinco a doze segundos. O projeto removeu essas distrações sem transformar o sistema em um folheto estático.

[INSERIR IMAGEM 1 — fluxo Lean UX e telas do leitor, mostrando a relação entre descoberta, performance e foco.]

## Static-first, não static-only

O projeto usa MySQL como fonte da verdade e PHP como camada de compilação. Mais de 31 mil versículos podem ser renderizados em páginas HTML semânticas, eliminando consultas ao banco no caminho principal de leitura. A busca continua dinâmica, enquanto preferências de acessibilidade e estado de leitura persistem no navegador.

```bash
[ MySQL Cloud Db ] ──(Local Compilation Engine)──> [ In-Memory Buffer (ob_start) ]
│
▼
[ GitHub (main) ] <──(Decoupled Logic Dev)        [ /public Static Asset Matrix ]
│
▼ (Automated Deployment Vector)
[ Hostinger Server (deploy) ]
```

O deploy mantém caminhos limpos para idioma e livro, URLs canônicas e links `hreflang` para indexação global. A arquitetura é deliberadamente simples: servidor compartilhado, orçamento mensal baixo e um compilador que faz o trabalho pesado antes da chegada do leitor.

## Leitura como interface silenciosa

A pesquisa com pastores, educadores, estudiosos e leitores casuais mostrou três tarefas dominantes: ler em sequência, encontrar um versículo e trocar de tradução. Isso definiu a superfície do produto. Times New Roman atende à leitura longa; Arial cuida dos controles; modo escuro, ajuste de fonte, direção de leitura e navegação por teclado ficam disponíveis sem competir com o texto.

[INSERIR IMAGEM 2 — leitor em modo claro e escuro, com controles de acessibilidade e troca de tradução.]

O compartilhamento atende aos dois contextos: uma URL canônica para estudo e uma imagem gerada para conversas sociais. A interface não usa anúncios, doações ou paywall.

## Uma pequena camada de roteamento

A saída estática é servida diretamente, enquanto o Apache direciona a rota de busca para o endpoint dinâmico:

```apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^search$ search.php [L,QSA]
```

## Resultado

O Testamentus alcançou First Contentful Paint de 0,9s e resultado 100/100 no PageSpeed na validação original, com trabalho de WCAG AA direcionado a um score de acessibilidade de 92/100. O resultado é uma plataforma que pode crescer em idiomas sem tirar a atenção do leitor do texto.
