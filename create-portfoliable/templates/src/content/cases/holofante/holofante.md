# Holofante: turning a studio into a system

Holofante started with a practical constraint: grow an applied design lab without hiring an administrative layer. Proposals, contracts, invoices, approvals, and delivery status were distributed across conversations and tools. Each new project created more coordination work.

The answer was to treat the operation as a product. The system connected the quote-to-cash lifecycle to a shared project state, so clients and the studio could see what had happened, what was blocked, and what needed action next.

[INSERIR IMAGEM 1 — ciclo completo do cliente, do lead ao pós-venda, com os pontos de automação destacados.]

## DesignOps as infrastructure

The first decision was to build a multi-state component framework instead of a collection of project-specific screens. The same interface could represent a paused project, a client action, an approval, an error, or an offline fallback. This made the system consistent across the eight project milestones and reduced the cost of adding a new workflow.

The second decision was state-driven rendering. Backend state—proposal, contract, payment, and delivery—determined which component and action appeared. A signed contract could unlock the next step without a separate page or manual status update.

[INSERIR IMAGEM 2 — arquitetura de estados mostrando como proposta, contrato, pagamento e entrega mudam a interface.]

## Automation with boundaries

Notion became the source of truth for project records, while Node.js serverless functions connected it to payments, signatures, notifications, and client-facing views. UUIDs and encrypted sensitive fields kept proposal values out of guessable public URLs.

The system was intentionally built inside the existing JavaScript ecosystem and under real client work. That constraint favored small, composable automations over a large platform rewrite.

## Outcome

Holofante grew MRR by 340%, recovered more than ten hours per week, and supported twelve simultaneous projects. The result was not only faster administration: it gave a service business a repeatable operating model where design, engineering, and operations shared the same states.

# Holofante: transformando um estúdio em sistema

O Holofante começou com uma restrição prática: fazer um applied lab de design crescer sem contratar uma camada administrativa. Propostas, contratos, cobranças, aprovações e status de entrega ficavam espalhados entre conversas e ferramentas. Cada projeto novo criava mais trabalho de coordenação.

A resposta foi tratar a operação como produto. O sistema conectou o ciclo quote-to-cash a um estado compartilhado de projeto, para que cliente e estúdio soubessem o que aconteceu, o que estava bloqueado e qual ação vinha a seguir.

[INSERIR IMAGEM 1 — ciclo completo do cliente, do lead ao pós-venda, com os pontos de automação destacados.]

## DesignOps como infraestrutura

A primeira decisão foi construir um framework de componentes multiestado, em vez de telas específicas para cada projeto. A mesma interface podia representar um projeto pausado, uma ação do cliente, uma aprovação, um erro ou um fallback offline. Isso trouxe consistência aos oito marcos do projeto e reduziu o custo de criar novos fluxos.

A segunda decisão foi renderizar a interface a partir dos estados. Proposta, contrato, pagamento e entrega determinavam qual componente e qual ação apareciam. Um contrato assinado podia liberar a próxima etapa sem outra página ou atualização manual.

[INSERIR IMAGEM 2 — arquitetura de estados mostrando como proposta, contrato, pagamento e entrega mudam a interface.]

## Automação com fronteiras

O Notion virou fonte da verdade dos projetos, enquanto funções serverless em Node.js conectavam registros a pagamentos, assinaturas, notificações e visões para clientes. UUIDs e campos sensíveis criptografados mantinham valores fora de URLs públicas previsíveis.

O sistema foi construído dentro do ecossistema JavaScript existente e em paralelo ao atendimento de clientes. Essa restrição favoreceu automações pequenas e composáveis, em vez de uma reescrita completa da plataforma.

## Resultado

O Holofante aumentou o MRR em 340%, recuperou mais de dez horas por semana e suportou doze projetos simultâneos. O resultado não foi apenas administrar mais rápido: foi dar a um negócio de serviços um modelo operacional repetível, no qual design, engenharia e operação compartilham os mesmos estados.
